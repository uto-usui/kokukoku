# Kokukoku プロダクト戦略ピボット

> **旧戦略**: 1,500円 / $9.99 買い切り。アプリ売上が収益の中心。
> **新戦略**: 無料ローンチ → 有料化。アプリは「名刺」。LP（Web版タイマー + Patreon）が収益の中心。制作者ブランディングが主目的。

---

## 1. ビジネスモデル設計

### 1-1. なぜピボットするのか

旧戦略の最大のリスクは「無名の個人制作者が有料アプリで認知を獲得する困難さ」にあった。

| 旧戦略の前提 | 現実 |
|---|---|
| 1,500円でも品質が伝われば売れる | App Store の検索アルゴリズムは DL 数重視。有料アプリは無料に比べて DL 数が桁違いに少なく、検索順位が上がらない。新規の無名アプリが有料のまま上位に表示されることは極めて稀 |
| Product Hunt / Hacker News で初動を作る | 可能だが一過性。継続的な流入を生むには「App Store 内の検索順位」が必須であり、そのためには DL 数が必要 |
| Apple フィーチャーで一気に露出 | フィーチャー獲得は確率が低い。獲得できなかった場合のプラン B がない |
| 1,500円 x 月 200 DL = 年 360 万円 | 無名アプリの月 200 有料 DL は非常に楽観的。現実的には月 20-50 DL が妥当 |

新戦略は、この「にわとりと卵」問題を正面から解く。まず DL 数を最大化し、App Store 内での可視性を確保した上で、十分な社会的証明（レビュー数・評価）が蓄積されてから有料化する。アプリ売上よりも「制作者 okiniirinoao の認知獲得」を最優先する。

### 1-2. 無料 → 有料の切り替え基準

有料化のトリガーは「単一指標」ではなく、複数条件の AND で判断する。

| 条件 | 閾値 | 理由 |
|---|---|---|
| **累計 DL 数** | 1,000 DL 以上 | App Store の検索順位が安定し、オーガニック流入が自走し始める最低ライン。これ以下で有料化すると検索順位が急落し、新規流入が途絶える |
| **レビュー数** | 50 件以上（日英合算） | 50 件を超えると App Store の検索結果に星評価が安定表示される。星 4.5 以上を維持していることが前提 |
| **平均評価** | 4.5 以上 | 有料化後に「無料だった頃は良かったのに」という低評価レビューが増えるリスクを、既存の高評価バッファで吸収するため |
| **LP のトラフィック** | 月間 500 UU 以上 | LP 経由の Patreon 転換が機能し始めている証拠。アプリ有料化前に Patreon の収益基盤ができていることが望ましい |
| **経過期間** | ローンチ後 3-6 ヶ月 | 短すぎると DL 数が足りない。長すぎると「永久無料」の印象が固まり有料化の反発が大きくなる |

**推奨タイミング**: 上記 5 条件のうち 4 つ以上を満たした時点。ただし「経過期間 6 ヶ月」を超えた場合は、他の条件が未達でも有料化を検討する（無料期間が長すぎると有料化のハードルが指数的に上がるため）。

### 1-3. 有料化時の最適価格

| 価格 | メリット | デメリット | 推奨度 |
|---|---|---|---|
| **100円 / $0.99** | 心理的抵抗が最小。DL 数の減少幅が最も小さい | Apple の 30% 手数料後の手取りが 70 円。収益としてほぼ意味がない。「安い = 価値が低い」というシグナルになりうる | --- |
| **200円 / $1.99** | 缶コーヒー 1 杯の心理価格帯。学生でも払いやすい | 手取り 140 円。収益は限定的だが「有料アプリ」としての体裁は成立する | -- |
| **300円 / $2.99** | コンビニスイーツの心理価格帯。Productivity アプリとして違和感のない価格 | 旧戦略の 1,500 円からの落差が大きいが、これは「ピボット後」の文脈では問題にならない | **推奨** |
| **500円 / $4.99** | 手取り 350 円。月 100 DL で年間 42 万円。ブランド価値を維持しやすい | 無料 → 500 円の落差が大きく、有料化時の反発リスクが最大 | - |

**結論: 300円 / $2.99 を推奨。**

理由:
- 新戦略ではアプリ売上は主要な収益源ではない。Patreon / 投げ銭が収益の中心
- 300 円は「象徴的な対価」として機能する。無料との差別化（低品質レビューのフィルタリング）には十分だが、DL 数を大きく減らさない
- ユニバーサル購入（iOS + macOS + watchOS）で 300 円は、ユーザーにとって明確にお得感がある
- Things 3 (3,800 円) や Bear (年 2,500 円) と並ぶ「クラフトツール」のポジショニングは維持しつつ、価格の敷居を極限まで下げる

### 1-4. 有料化後の既存ユーザーへの影響

| 対象 | 影響 | 対策 |
|---|---|---|
| **無料期間中に DL したユーザー** | 影響なし。一度 DL したアプリは有料化後も引き続き使える。アップデートも無料で受けられる | App Store の仕様として自動的に保護される。特別な対策は不要 |
| **有料化後の新規ユーザー** | 300 円の支払いが必要 | 無料期間中のレビュー・評価が「社会的証明」として機能し、300 円の価値を正当化する |
| **口コミへの影響** | 「無料だったから」という理由でおすすめしていた人が、有料化後に紹介しにくくなる可能性 | LP 上の Web 版タイマーは永久無料。「まず Web で試して、気に入ったらアプリへ」という動線が有料化後も維持される |

### 1-5. 有料化の告知設計

有料化は「突然の値上げ」ではなく「予告された自然な移行」として演出する。

| タイミング | アクション |
|---|---|
| **ローンチ時** | App Store 説明文とLPに「期間限定無料」と明記。「いずれ有料化する」ことを最初から宣言しておくことで、有料化時の反発を大幅に軽減 |
| **有料化 2 週間前** | プロモーションテキスト（審査なしで変更可能）を更新。「まもなく有料化。今なら無料で手に入れられます」。SNS でも告知。駆け込み DL による最後の DL 数ブーストを狙う |
| **有料化当日** | 価格を 300 円に変更。プロモーションテキストを「期間限定無料でお試しいただいた皆さまに感謝」に更新。LP のコピーも更新 |

## 2. LP 戦略

### 2-1. LP の役割定義

LP は 4 つの役割を同時に果たす。優先順位は以下の通り。

| 優先度 | 役割 | 具体的な機能 |
|---|---|---|
| 1 | **Web 版ポモドーロタイマー** | ブラウザで実際に動くタイマー。アプリの「無料トライアル」として機能する。SEO 流入の主力エンジン |
| 2 | **App Store 動線** | App Store バッジ + スクリーンショット + 「iPhoneで続きを」の CTA。Web 版で体験したユーザーをアプリに誘導 |
| 3 | **制作者ブランディング** | okiniirinoao のプロフィール、制作ストーリー、ポートフォリオへのリンク。「誰が作ったか」が見える |
| 4 | **Patreon / 投げ銭** | 「このアプリを気に入ったら」という文脈での支援動線。押し付けがましくなく、でも見つけやすく |

### 2-2. ファネル設計

```
[SEO / SNS / Product Hunt]
        |
        v
    LP に到着
        |
        v
  Web版タイマーを使う  -----> 気に入らない → 離脱（それでも okiniirinoao の認知は残る）
        |
        v
  気に入った
        |
   +-----------+-----------+
   |           |           |
   v           v           v
App Store   Patreon    SNS フォロー
DL動線     支援動線    制作者認知
```

**ファネルの核心**: Web 版タイマーが「無料トライアル」として機能することで、アプリが有料化された後も「まず Web で試す → 良ければアプリを買う」という導線が維持される。これは旧戦略で課題だった「試す前に買う不安」を完全に解消する。

### 2-3. LP のページ構成

| セクション | 内容 | 目的 |
|---|---|---|
| **Hero** | Web版タイマーがそのまま動いている。「Kokukoku -- 時を刻む、ただそれだけ。」のタグライン。Start ボタンを押せばすぐにポモドーロが始まる | ファーストビューで「使える」ことを伝える。直帰率を下げる |
| **App Store 動線** | iPhone / Mac / Apple Watch のスクリーンショット。App Store バッジ。「Web で試して、アプリで続けよう」 | Web → アプリへの転換 |
| **About** | 「Kokukoku は okiniirinoao が一人で作っている」。制作背景、設計思想（引き算、Apple-native、データ収集なし）。顔写真は不要、ハンドルネームとアイコンで十分 | 制作者の人格を見せる。Things 3 / Raycast 層は「作り手が見える」ことに価値を感じる |
| **Support** | 「気に入ったら、応援してください」。Patreon リンク + 他の投げ銭リンク。ティア説明 | 収益動線。About セクションの直後に置くことで「この人を支援したい」という動機と接続する |
| **Footer** | プライバシーポリシー、サポート連絡先、GitHub リンク | 法的要件 + 信頼性 |

### 2-4. SEO 戦略

LP 上の Web 版タイマーは、SEO 流入の主力エンジンとなる。

| ターゲットキーワード | 言語 | 検索意図 | LP での対応 |
|---|---|---|---|
| 「ポモドーロ タイマー オンライン」 | JA | ブラウザでポモドーロを使いたい | Web 版タイマーが直接応答 |
| 「ポモドーロ タイマー」 | JA | ポモドーロタイマーを探している | Web 版 + アプリへの動線 |
| "pomodoro timer online" | EN | ブラウザでポモドーロを使いたい | Web 版タイマーが直接応答 |
| "pomodoro timer" | EN | ポモドーロタイマーを探している | Web 版 + アプリへの動線 |
| 「集中 タイマー」「勉強 タイマー」 | JA | 集中用のタイマーを探している | Web 版 + アプリへの動線 |

**技術的な SEO 対策**:
- SSR (Server-Side Rendering) または SSG (Static Site Generation) でビルド。SPA のみだと検索エンジンがインデックスしにくい
- `<title>` と `<meta description>` にターゲットキーワードを含める
- 構造化データ (JSON-LD) で SoftwareApplication スキーマをマークアップ
- og:image にアプリのヒーロースクリーンショットを設定

## 3. Web 版タイマーのスコープ

### 3-1. 設計方針: 「お試し版」であり「完全版」ではない

Web 版の目的は 2 つ:
1. **ブラウザだけで使いたい人に、十分に使えるタイマーを提供する**（SEO 流入の受け皿）
2. **アプリでしかできない体験の存在を示し、アプリへの誘導動機を作る**

この 2 つは矛盾しない。Web 版が「使えない」レベルだと離脱される。Web 版が「アプリと同じ」だとアプリの存在意義がなくなる。**Web 版は「80% の体験」を提供し、残りの 20% でアプリへの誘導動機を作る**。

### 3-2. 機能スコープ

| 機能 | Web 版 | アプリ版 | Web 版で省く理由 |
|---|---|---|---|
| **基本タイマー** (Focus / Short Break / Long Break) | あり | あり | -- |
| **自動サイクル** (Focus → Break → Focus...) | あり | あり | -- |
| **サイクル表示** (2 / 4 等) | あり | あり | -- |
| **キーボードショートカット** (Space で Start/Pause) | あり | あり | -- |
| **Vibrant material + grain texture** | あり（CSS で再現） | あり | ブランドの一貫性のため Web でも再現する |
| **100pt thin-weight 数字** | あり（SF Pro / system-ui） | あり | -- |
| **ピンクノイズ** | あり（Web Audio API） | あり | Voss-McCartney アルゴリズムで生成。Start 押下時に AudioContext 初期化 |
| **ダークモード** | あり（prefers-color-scheme） | あり | CSS カスタムプロパティでテーマ切り替え |
| Live Activity / Dynamic Island | **なし** | あり | ネイティブ API。Web では不可能 |
| Apple Watch 同期 | **なし** | あり | ネイティブ API。Web では不可能 |
| Widget | **なし** | あり | ネイティブ API。Web では不可能 |
| Focus Mode 連携 | **なし** | あり | ネイティブ API。Web では不可能 |
| MenuBarExtra | **なし** | あり | ネイティブ API。Web では不可能 |
| セッション履歴 | **なし** | あり | Cookie・localStorage は一切使わない。ページリロードでリセット。アプリへの誘導動機 |
| ブラウザ通知 | **なし** | あり | Notification API は不使用。許可ダイアログがブランド体験を壊す。代わりにタブタイトル更新 + 完了音で通知 |
| Boundary Stop Policy | **なし** | あり | Web 版はシンプルに保つ |

### 3-3. Web 版の「アプリへの誘導」UI

Web 版タイマーの下部に、控えめだが目に入る位置で:

```
--------------------------------------------
もっと集中したい？

Live Activity、Apple Watch、ピンクノイズ、セッション履歴。
アプリなら、すべてが揃う。

[App Store でダウンロード]
--------------------------------------------
```

- 初回表示時は非表示。タイマーを 1 回以上完了した後に表示する（「使ってから勧める」）
- 閉じるボタンあり。閉じたら二度と表示しない（localStorage で記憶）
- 押し付けがましさの排除が最重要。Kokukoku のブランド（静謐・無装飾）と矛盾する要素は一切入れない

### 3-4. 技術スタック

| 選択肢 | 評価 |
|---|---|
| **Next.js Static Export（推奨）** | React + TypeScript で開発。`next export` で完全静的出力。独自フォーマットの学習不要。標準的な開発体験 |
| Astro | 静的サイト生成に特化。ゼロ JS デフォルトは魅力的だが、独自の .astro ファイルフォーマットの学習コストがある |
| SvelteKit | 軽量で良い選択肢だが、React エコシステムとの互換性がない |
| 素の HTML/CSS/JS | 最もシンプルだが、コンポーネント化やビルド最適化がない |

**ホスティング**: Cloudflare Pages または Vercel。無料枠で十分。カスタムドメイン対応。

## 4. 制作者ブランディング戦略

### 4-1. okiniirinoao というブランドの定義

| 属性 | 方針 |
|---|---|
| **名前** | okiniirinoao（おきにいりのあお）。日本語の響きと意味を持つが、ローマ字表記でグローバルに通用する |
| **領域** | Apple プラットフォームのクラフトアプリ制作者。「引き算のデザイン」「Apple-native」「プライバシー尊重」が一貫したテーマ |
| **トーン** | アプリと同じ。静謐、端正、語りすぎない。SNS でも感嘆符や絵文字は最小限。技術的な深さを淡々と語る |
| **顔出し** | しない。ハンドルネームとアイコンで活動する。匿名性は「道具が主役」というブランドと整合する |

### 4-2. 認知獲得のロードマップ

無名の個人が認知を獲得するには、「作品の品質」と「発信の一貫性」の掛け算が必要。

#### Phase 1: ローンチ前（~ローンチ日）

| アクション | チャネル | 目的 |
|---|---|---|
| 開発過程の発信 | X (Twitter)、Threads | 「作っている人がいる」という認知の種まき。WIP スクリーンショット、設計判断の断片、SwiftUI Tips |
| 技術ブログ記事 | Zenn / **note.com** / 個人ブログ | SEO 資産の構築。「SwiftUI で Live Activity を実装する」「macOS MenuBarExtra の設計」等、技術スタックを切り口にした記事。**note.com は投げ銭機能付きで発信と支援を一体化** |
| LP 公開 | Web | Web 版タイマーの先行公開。「アプリはまだだけど Web で使える」 |

#### Phase 2: ローンチ直後（1-4 週）

| アクション | チャネル | 目的 |
|---|---|---|
| Product Hunt 投稿 | Product Hunt | 英語圏の初動。「Japanese indie dev, zero dependencies, no data collected」がストーリー |
| Hacker News Show HN | Hacker News | ナレッジワーカー層への直接訴求。「Show HN: I built a Pomodoro timer with zero third-party dependencies」 |
| App Store 無料ランキング | App Store | 無料アプリとして Productivity カテゴリの上位を狙う。旧戦略では不可能だったこと |
| 日本語 SNS | X、Threads | 日本語圏での認知。「一人で作りました」「データ収集ゼロ」が共感を呼ぶ文脈 |
| 開発ストーリー連載 | **note.com** | 開発の背景・設計判断・個人開発の試行錯誤を記事化。投げ銭機能で支援を受けつつ認知を拡大 |

#### Phase 3: 成長期（1-6 ヶ月）

| アクション | チャネル | 目的 |
|---|---|---|
| 定期的な技術発信 | Zenn / **note.com** / ブログ | 「Kokukoku の作者」として技術コミュニティでの認知を確立。note.com 記事への投げ銭が継続的な支援収益に |
| アプリのアップデート | App Store | 定期的なアップデートで「メンテナンスされている」信頼を構築。What's New が無料の広告枠として機能 |
| ユーザーとの対話 | GitHub Issues / X | 「作り手が見える」体験。バグ報告への丁寧な対応、機能要望の取捨選択を公開で行う |
| 次のアプリの予告 | LP / SNS | Kokukoku が「okiniirinoao の最初の作品」であることを示し、ブランドの拡張を予感させる |

### 4-3. Kokukoku をポートフォリオとして使う

Kokukoku は「アプリ」であると同時に「okiniirinoao の技術力と設計思想を証明するポートフォリオ」である。

| 証明したいこと | Kokukoku が証明する方法 |
|---|---|
| Apple プラットフォームの深い理解 | iPhone + Mac + Watch + Widget + Live Activity + Focus Mode の統合。Mac Catalyst ではなくネイティブ macOS |
| 設計品質 | Vibrant material、100pt thin-weight typography、numericText transition |
| エンジニアリング品質 | サードパーティ依存ゼロ。SwiftUI + SwiftData。テスト可能なアーキテクチャ |
| プライバシーへの姿勢 | Data Not Collected。分析 SDK なし |
| 持続可能性 | 定期的なアップデート。ユーザーとの対話 |

## 5. Patreon / 投げ銭設計

### 5-1. なぜ Patreon か

| 収益手段 | Apple 手数料 | 設置場所の制約 | 推奨度 |
|---|---|---|---|
| App Store IAP (Tip Jar) | **30%** | アプリ内に設置必須 | 非推奨。手数料が高すぎる |
| Patreon | **8-12%**（プラン次第）+ 決済手数料 | LP に設置。アプリ内からのリンクは Apple ガイドライン上グレー | **推奨** |
| Buy Me a Coffee | **5%** + 決済手数料 | LP に設置 | 補助的に併用可 |
| GitHub Sponsors | **0%**（GitHub が手数料負担） | LP + GitHub プロフィール | **補助的に推奨** |
| PayPal.me / Stripe | 決済手数料のみ | LP に設置 | 導入の手間が大きい |
| **note.com** | 投げ銭手数料（作者90% / note 10%） | note.com 記事ページ | 日本のブログプラットフォーム。記事投げ銭機能がビルトイン。開発ストーリー発信と投げ銭を一体化 | **日本向けメイン** |

**結論**: **note.com** を日本向けメインの発信・投げ銭プラットフォームとして活用。開発ストーリー記事を定期的に投稿し、記事のビルトイン投げ銭機能で支援を受ける。Patreon はグローバル向けのサブ、GitHub Sponsors は開発者コミュニティ向けとして併用。

### 5-2. Patreon ティア設計

ティアは「シンプル」が最重要。選択肢が多いと離脱する。

| ティア | 月額 | 特典 | 設計意図 |
|---|---|---|---|
| **Supporter** | $3 / 月 | 月 1 回の開発レター（次のアップデート内容、設計判断の裏側、次のアプリの構想）。Patreon 限定の壁紙（Kokukoku の UI 要素を使ったミニマルデスクトップ壁紙） | 「応援する」という行為そのものに価値を感じる層。コーヒー 1 杯の価格。特典は「もらえたら嬉しいけど、なくても支援する」レベルに留める |
| **Builder** | $10 / 月 | Supporter の全特典 + 新機能の優先投票権（GitHub Discussions での投票に加重）。開発過程のデイリーログ（Notion / GitHub Projects へのアクセス） | 「作る過程を見たい」「方向性に関わりたい」層。okiniirinoao のもう一つの作品（制作過程そのもの）を楽しむ |

**作らないティア**:
- $1 / 月: 安すぎて Patreon の手数料で消える。支援者にも「意味がある額を払っている」感覚が薄い
- $25+ / 月: 個人のアプリ制作者への月額としては高すぎる。該当者がほぼいない
- 物理グッズ付きティア: 配送の手間がソロ開発者にとって致命的。やらない

### 5-3. 投げ銭の見せ方

**原則: 「見つけやすいが、押し付けない」**

Kokukoku のブランド（静謐・無装飾）と矛盾する投げ銭 UI は絶対に避ける。

#### LP での表示

```
--------------------------------------------
Kokukoku を気に入ってくれたら

okiniirinoao は一人でアプリを作っています。
サポートは、次のアプリを作る力になります。

[Patreon で応援する]  [GitHub Sponsors]
--------------------------------------------
```

- About セクションの直後に配置
- 背景色はページと同じ白。特別な装飾はしない
- CTA ボタンは Kokukoku のボタンスタイル（.bordered、カプセル型）を踏襲
- 金額は LP 上に書かない。Patreon のページで初めて金額が見える

#### アプリ内での扱い

Apple のガイドライン上、アプリ内から外部課金への誘導は制限がある。ただし 2024 年以降の EU DMA 対応でルールが流動的。

**安全な方法**: アプリの Settings 画面に「Web サイト」リンクを設置。LP に飛ばし、LP 上で Patreon への動線を提示する。アプリ内で直接「支援してください」とは言わない。

### 5-4. 収益シミュレーション

| 指標 | 保守的 | 標準的 | 楽観的 |
|---|---|---|---|
| LP 月間 UU | 500 | 2,000 | 10,000 |
| Patreon 転換率 | 0.5% | 1.0% | 2.0% |
| Patreon 支援者数 | 2-3 人 | 20 人 | 200 人 |
| 平均単価 | $5 / 月 | $5 / 月 | $5 / 月 |
| 月間 Patreon 収益 | $10-15 | $100 | $1,000 |
| 年間 Patreon 収益 | $120-180 | $1,200 | $12,000 |

**現実的な期待値**: ローンチ初年度は「保守的」~「標準的」の間。Patreon 単体で生活費を賄うのは非現実的。**しかしそれでいい**。新戦略の主目的は収益ではなく「制作者としての認知獲得」であり、Patreon の収益はその副産物。

## 6. リスクと対策

### 6-1. 無料アプリの低品質レビューリスク

**リスク**: 無料アプリは有料アプリに比べて DL のハードルが低い分、「ポモドーロを知らない」「自分には合わなかった」というカジュアルな低評価レビューが増える。有料アプリの 1,500 円という価格は自然なフィルターとして機能していたが、無料にすることでこのフィルターが消える。

**対策**:

| 対策 | 効果 | 実装コスト |
|---|---|---|
| **App Store のレビュー返信を丁寧に行う** | 低評価レビューに対して冷静かつ建設的に返信することで、閲覧者に「メンテされている」印象を与える。Apple は返信があるアプリを好む傾向がある | 低（時間のみ） |
| **アプリ内のレビュー依頼タイミングを最適化** | SKStoreReviewController の表示タイミングを「ポモドーロ 5 サイクル完了後」に設定。実際に使い込んだユーザーにのみレビューを促すことで、高評価レビューの比率を上げる | 低（コード変更のみ） |
| **LP と App Store 説明文で「ポモドーロタイマーです」を明確に** | 「タイマーアプリ」ではなく「ポモドーロテクニック専用」であることを明示し、汎用タイマーを求めるユーザーの期待値ずれを防ぐ | 低（コピー変更のみ） |
| **有料化そのもの** | 有料化後は価格フィルターが復活する。有料化前にレビュー数を十分に稼いでおけば、有料化後の低評価レビューの比率は希釈される | -- |

### 6-2. 有料化時の反発リスク

**リスク**: 無料で使い始めたユーザーが「金を取るようになった」と感じ、低評価レビューを投稿する。Reddit や SNS で「改悪」として拡散されるリスクがある。

**対策**:

| 対策 | 効果 |
|---|---|
| **ローンチ時から「期間限定無料」と明記** | 有料化は「約束通り」であり「裏切り」ではないという文脈を最初から作る。最も重要な対策 |
| **既存ユーザーは無料のまま** | App Store の仕様として、一度 DL したアプリは有料化後も無料で使える。これを明示的にアナウンスする。「今 DL すれば永久無料」は駆け込み DL の強力なインセンティブにもなる |
| **有料化価格を抑える** | 300 円は反発を最小化する価格。「高い」と感じるユーザーが少ない |
| **有料化と同時に新機能を追加** | 「有料化 = 何かが減る」ではなく「有料化 = さらに良くなる」というフレーミング。例: 有料化と同時にテーマカスタマイズや統計機能を追加 |

### 6-3. Patreon の低転換率リスク

**リスク**: Patreon の一般的な転換率は 1-3%（フォロワー比）。LP の UU ベースではさらに低い。月額 $3 のティアでも、十分な支援者数を集めるのは困難。

**対策**:

| 対策 | 効果 |
|---|---|
| **Patreon を「主要収益源」と位置づけない** | 期待値を正しく設定する。Patreon は「ゼロよりは多い」程度の副収入。主目的はブランディングと支援者との関係構築 |
| **GitHub Sponsors を併用** | GitHub Sponsors は手数料 0%。技術者コミュニティとの親和性が高い。Patreon が「クリエイター支援」の文脈なら、GitHub Sponsors は「OSS 的な支援」の文脈 |
| **支援者限定コンテンツの質を上げる** | 開発レターの内容を「支援していなくても一部は見られるが、全文は支援者限定」にすることで、転換のインセンティブを作る |
| **長期的にアプリ数を増やす** | Kokukoku 1 つだけでは支援者が限られる。2 つ目、3 つ目のアプリが出ることで「okiniirinoao のファン」が増え、Patreon の転換率が上がる |

### 6-4. Web 版タイマーがアプリの DL を食うリスク

**リスク**: Web 版が十分に使えると、ユーザーがアプリを DL する動機がなくなる。特にデスクトップユーザーは Web 版で完結してしまう可能性がある。

**対策**:

| 対策 | 効果 |
|---|---|
| **Web 版のスコープを意図的に制限** | ピンクノイズ、セッション履歴、Boundary Stop Policy は Web 版に含めない。「もっと使いたいならアプリへ」の動機を維持 |
| **モバイルからの LP アクセスに App Store 動線を強調** | モバイル UA を検出し、App Store バッジをより目立つ位置に配置。スマホでブラウザのタイマーを使うのは体験が悪い（通知の信頼性、バックグラウンド制限）ことをユーザーは自然に感じる |
| **Web 版は「入り口」と割り切る** | Web 版が多く使われること自体は、SEO 順位の向上、LP トラフィックの増加、ブランド認知の拡大につながる。アプリの DL が減っても、ファネル全体では正しい |

### 6-5. Apple ガイドラインとの抵触リスク

**リスク**: アプリ内から外部課金（Patreon）への誘導が Apple のガイドラインに抵触する可能性。

**対策**:

| 対策 | 効果 |
|---|---|
| **アプリ内で Patreon を直接リンクしない** | Settings 画面に「Web サイト」リンクのみ設置。LP 経由で Patreon にたどり着く設計。これなら Apple のガイドラインに抵触しない |
| **アプリ内で「支援」「寄付」の文言を使わない** | 「Web サイトを見る」「開発者について」のような中立的な文言に留める |
| **IAP (Tip Jar) をやらないことで審査リスクを回避** | IAP を実装しないことで、IAP 関連の審査ポイント自体が消える |

### 6-6. 無料期間が長引くリスク

**リスク**: DL 数やレビュー数が閾値に達しないまま時間が経過し、有料化のタイミングを逸する。「永久無料」の印象が固まると、有料化時の反発が極大化する。

**対策**:

| 対策 | 効果 |
|---|---|
| **最長 6 ヶ月の期限を設定** | 条件未達でも 6 ヶ月で有料化する。これを事前に宣言しておく |
| **月次で進捗をトラッキング** | DL 数、レビュー数、LP トラフィック、Patreon 支援者数を月次で確認し、有料化の意思決定を先延ばしにしない |
| **有料化が不要になるシナリオも受け入れる** | Patreon 収益が十分であれば、アプリは永久無料のままでもよい。有料化は「必須」ではなく「オプション」 |
