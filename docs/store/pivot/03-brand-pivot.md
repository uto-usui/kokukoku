# Kokukoku ブランドピボット: LP + Web版タイマー + 支援モデル

> 本ドキュメントは、有料アプリから「期間限定無料 → 後に有料化」への方針転換に伴い、CDO / アートディレクターが策定するビジュアル戦略の改訂版である。ランディングページ（LP）の新規制作、LP上で動作するWeb版ポモドーロタイマー、Patreon/投げ銭動線、App Store スクリーンショットの修正方針を含む。

---

## 1. LPのデザインディレクション

### 1-1. 設計思想

LPは「アプリの延長」ではなく「アプリの世界に入る前の庭」として設計する。アプリ内で実現しているVibrant material surface + grain textureの静謐さを、Webの技術でゼロから再構築する。訪問者はLPに着地した瞬間、まだアプリをダウンロードしていないにもかかわらず、Kokukokuの「触り心地」を体感する。

核心的な原則: **LPそのものがプロダクトの品質証明である。**

Things 3やLinearのLPが参照点。過剰な装飾を排し、プロダクトを「そのまま見せる」ことで品質を語る。

### 1-2. ページ構成

LPは7セクションの縦一本スクロールで構成する。各セクションは画面高さの100vh以上を使い、セクション間に十分な余白（120px以上）を確保する。

| 順序 | セクション | 役割 | 滞在目標 |
|---|---|---|---|
| **S1** | ヒーロー | 「何であるか」を1秒で伝える。タグライン + App Store DLボタン + スクロール誘導 | 3秒 |
| **S2** | Web版タイマー（実動） | LP上で実際にポモドーロタイマーを使える。「触ればわかる」体験 | 25分（最長） |
| **S3** | フィーチャーギャラリー | Apple エコシステム統合を3-4カードで見せる。Live Activity、Watch、MenuBar、Widget | 8秒 |
| **S4** | フィロソフィー | 「なぜ引き算なのか」。ブランドの設計思想を短い散文で語る | 12秒 |
| **S5** | 制作者紹介 | 個人開発者としてのストーリー。顔ではなく「手」で語る | 6秒 |
| **S6** | 支援セクション | Patreon / 投げ銭。「応援する」という選択肢を静かに提示 | 4秒 |
| **S7** | フッター | App Store DLボタン（2回目）、プライバシーポリシー、サポート、SNSリンク | -- |

**設計上の帰結:**

- S1とS2の境界を曖昧にする。ヒーローのタイマー表示がそのままWeb版タイマーに遷移する感覚。スクロールするとidle状態のタイマーが「使える」状態になる。
- S3は横スクロールカルーセルではなく、縦に並べたカード。モバイルでの操作性を優先。
- S5→S6の流れが自然になるよう、制作者の思いから支援への接続を「物語の延長」として設計する。
- App Store DLボタンはS1とS7の2箇所のみ。中間に挟まない。静かに佇む。

### 1-4. タイポグラフィ

| 用途 | 欧文 | 和文 | サイズ（デスクトップ） | ウェイト |
|---|---|---|---|---|
| **タイマー数字** | SF Mono / fallback: `ui-monospace, "Cascadia Mono", Menlo, monospace` | -- | 96px | 100 (Thin) |
| **H1（タグライン）** | Inter | Noto Sans JP | 48px | 300 (Light) |
| **H2（セクション見出し）** | Inter | Noto Sans JP | 32px | 300 (Light) |

**`.monospacedDigit()` のWeb翻訳:** `font-variant-numeric: tabular-nums;` をタイマー数字に適用。カウントダウン時に数字幅が変動しない。

**行間:** 本文は `line-height: 1.8`（和文の可読性を優先）。見出しは `1.3`。

### 1-5. レイアウトグリッド

```
デスクトップ（1200px+）: 12カラム、ガター 24px、左右マージン 120px
タブレット（768-1199px）: 8カラム、ガター 20px、左右マージン 48px
モバイル（-767px）: 4カラム、ガター 16px、左右マージン 20px
```

**コンテンツ最大幅:** 960px。これを超えるとコンテンツが左右に広がりすぎ、アプリの「コンパクトウィンドウ」感覚から乖離する。

**縦方向のリズム:** 8px グリッドに準拠。すべてのマージン・パディングは8の倍数。

### 1-6. アプリのデザイン言語をWebに翻訳する

#### Grain Texture

アプリの `.ultraThinMaterial` 上に見えるノイズテクスチャをWebで再現する。

```css
.grain-surface {
  position: relative;
  background: rgba(255, 255, 255, 0.72);
  backdrop-filter: blur(40px) saturate(1.2);
}
.grain-surface::after {
  content: '';
  position: absolute;
  inset: 0;
  background-image: url('/grain-128.png');
  background-repeat: repeat;
  opacity: 0.035;
  pointer-events: none;
  mix-blend-mode: multiply;
}
```

128x128px のノイズタイルをリピートし、`opacity: 0.035` で微かに重ねる。`mix-blend-mode: multiply` で背景色に馴染ませる。パフォーマンスへの影響は極小（1KB程度のPNG）。

#### Material Surface（ガラス表現）

`backdrop-filter: blur()` でアプリの Vibrant material を模倣する。タイマーカード、ボタンに適用。

```css
.glass-card {
  background: rgba(255, 255, 255, 0.65);
  backdrop-filter: blur(24px) saturate(1.1);
  border: 1px solid rgba(255, 255, 255, 0.3);
  border-radius: 20px;
  box-shadow: 0 2px 20px rgba(0, 0, 0, 0.04);
}
```

`backdrop-filter` 非対応ブラウザ（古いFirefox等）へのフォールバック: `background: rgba(245, 245, 245, 0.95)` で不透明に近いグレーを適用。グレインは引き続き表示。

#### Capsule Button

アプリの `Capsule().fill(.tertiary)` をWebで再現。

```css
.capsule-button {
  display: inline-flex;
  align-items: center;
  padding: 10px 28px;
  background: rgba(0, 0, 0, 0.05);
  border: none;
  border-radius: 9999px;
  font-size: 15px;
  font-weight: 500;
  color: #1A1A1A;
  cursor: pointer;
  transition: background 0.2s ease;
}
.capsule-button:hover {
  background: rgba(0, 0, 0, 0.08);
}
.capsule-button:active {
  background: rgba(0, 0, 0, 0.12);
  transform: scale(0.98);
}
```

#### アニメーション原則

- **トランジション:** すべて `ease` カーブ、200-400ms。
- **スクロールアニメーション:** `IntersectionObserver` で各セクションのフェードイン。`translateY(20px)` → `translateY(0)` + opacity。過度なパララックスは使わない。
- **タイマー数字:** CSS `font-variant-numeric: tabular-nums` + JavaScript による毎秒更新。数字の変化時に微かな `opacity` フェード（0.15秒）を入れ、アプリの `numericText` transition を想起させる。
- **禁止事項:** ローディングアニメーション、パーティクル、3Dエフェクト、マウスカーソル追従。ブランドの「無装飾」に反する。

### 1-7. レスポンシブ設計の方針

**モバイルファースト。** LP訪問者の70%以上がiPhoneからApp Storeリンク経由で来ると想定。

| ブレークポイント | タイマー数字サイズ | H1サイズ | コンテンツ幅 |
|---|---|---|---|
| モバイル（-767px） | 64px | 32px | 100% - 40px |
| タブレット（768-1199px） | 80px | 40px | 100% - 96px |
| デスクトップ（1200px+） | 96px | 48px | 960px |

**モバイル固有の設計:**

- S2（Web版タイマー）はモバイルでもフル機能動作。画面幅に合わせてタイマーカードが画面の80%幅を占める。
- S3（フィーチャーギャラリー）のカードは縦1列スタック。
- ナビゲーションバーなし。LPは一本道のスクロール体験。ハンバーガーメニューは存在しない。
- App Store DLボタンはモバイルで `position: sticky; bottom: 0` にしない。スクロールを邪魔しない。S1とS7に置くだけ。

## 2. Web版タイマーのUI設計

### 2-1. 設計思想

Web版タイマーは「アプリの体験版」ではなく「LPに住むタイマー」として設計する。アプリのすべてを再現しようとしない。Web版は「25分の集中を1回体験させる」ことだけに全力を注ぐ。

その1回の体験が、アプリ版のダウンロード動機になる。

### 2-2. ビジュアル仕様

```
+------------------------------------------+
|                                          |
|              Focus                       |  ← セッションラベル: 14px, #888888
|                                          |
|            24:38                          |  ← タイマー数字: 96px (desktop), Thin weight
|                                          |  ← tabular-nums, #1A1A1A
|                                          |
|         [ Pause ]  [ Reset ]             |  ← Capsule buttons, tertiary fill
|                                          |
|           ●  ○  ○  ○                     |  ← サイクルインジケーター: 4dots, 6px
|                                          |
+------------------------------------------+
   ↑ glass-card + grain-surface
```

**タイマーカードの仕様:**

| 要素 | 仕様 |
|---|---|
| カード幅 | デスクトップ: 400px / モバイル: 画面幅の85% |
| カード高さ | コンテンツに依存（約 360px） |
| 角丸 | 20px |
| 背景 | `rgba(255, 255, 255, 0.65)` + `backdrop-filter: blur(24px)` |
| グレイン | 128px ノイズタイル、opacity 0.035 |
| 影 | `0 2px 20px rgba(0, 0, 0, 0.04)` |
| 数字フォント | `ui-monospace` 系、96px、weight 100 |
| ボタンスタイル | Capsule、tertiary fill（`rgba(0,0,0,0.05)`） |

**状態遷移のビジュアル:**

| 状態 | タイマー数字色 | ラベル | ボタン |
|---|---|---|---|
| Idle | `#1A1A1A` | "Focus" | [ Start ] |
| Running (Focus) | `#1A1A1A` | "Focus" | [ Pause ] [ Reset ] |
| Running (Break) | `#1A1A1A` | "Short Break" / "Long Break" | [ Pause ] [ Skip ] |
| Paused | `#888888`（グレーアウト） | 状態維持 | [ Resume ] [ Reset ] |

### 2-3. アプリ版との一貫性と差別化

#### 一貫させるもの（ブランドの核）

- **タイマー数字:** 100pt thin weight、monospacedDigit。これがKokukokuのアイデンティティ。
- **Capsuleボタン:** tertiary fillのカプセル形状。
- **色彩:** モノトーン運用。有彩色なし。
- **余白:** 数字の上下に十分な空間。情報密度を下げる。
- **grain texture:** マテリアルサーフェスのノイズ感。
- **ピンクノイズ:** Web Audio API（Voss-McCartney アルゴリズム）でピンクノイズを生成。ユーザーが Start を押した時点で `AudioContext` を初期化し、自動再生制約をクリア。アプリ版と同じ集中体験を提供する。

#### Web版で省略するもの

- **設定画面:** 時間のカスタマイズ、Auto-start設定、境界停止ポリシー。Web版は25/5/15のデフォルト固定。
- **セッション履歴:** 記録しない。localStorage にも保存しない。
- **通知:** Notification APIは使わない。ブラウザ通知の許可ダイアログはブランド体験を壊す。代わりにタイマー完了時に画面上のビジュアルフィードバック（数字のパルスアニメーション + 控えめなサウンド）。
- **Live Activity / Widget / Watch:** アプリ専用機能。Web版に存在しないことが「アプリをダウンロードする理由」になる。
- **Focus Mode連携:** ブラウザでは不可能。
- ~~ピンクノイズ~~: 「一貫させるもの」セクションに移動済み。Web Audio API (Voss-McCartney) で搭載する。

#### Web版だけの演出

- **タブタイトル同期:** ブラウザタブのタイトルを `24:38 - Kokukoku` のようにリアルタイム更新。タブを切り替えても残り時間が見える。Webならではの体験。
- **完了時のビジュアル:** タイマー完了時、数字が `00:00` で一瞬止まった後、次のセッション（Break）にクロスフェード。アプリよりもわずかにドラマチックな演出。「もう一度やりたい」という気持ちを促す。
- **セッション完了後のナッジ:** 最初の1サイクル（Focus + Break）完了後、タイマーカードの下にごく控えめなテキスト: 「このリズムを、すべてのデバイスに。」+ App Storeバッジ。押し付けがましくなく、タイミングが自然。

### 2-4. 技術要件

- **フレームワーク:** Next.js の React コンポーネントとして実装。
- **時間モデル:** アプリと同じ `endDate` ベース。`Date.now()` と `endDate` の差分で残り時間を算出。`setInterval` ではなく `requestAnimationFrame` で描画し、バックグラウンドタブ復帰時にも正確な残り時間を表示。
- **Audio:** タイマー完了時の通知音（短い0.5秒、控えめな音）+ ピンクノイズ生成（Voss-McCartney アルゴリズム）。ユーザーが最初に Start を押した時点で `AudioContext` を初期化し、自動再生制約をクリア。
- **状態永続化:** なし。ページリロードでリセット。意図的にステートレス。

## 3. App Store スクリーンショット戦略の修正

### 3-1. 「無料」がメッセージに与える変化

有料アプリの場合、スクリーンショットは「1,500円の対価に見合う品質か」を証明する必要があった。無料アプリの場合、この心理的障壁が消える。代わりに必要なのは:

1. **「なぜ無料なのか」への暗黙の回答:** 品質が低いから無料なのではなく、品質が高いのに無料であるという「意外性」を伝える。
2. **ダウンロード後の体験への期待:** 無料はダウンロードの閾値を下げるが、起動後の第一印象が悪ければ即削除。SSの品質がそのまま「起動後に何が待っているか」の約束になる。
3. **支援への伏線:** 「これだけのものを無料で出す作り手」に対する敬意 → Patreon/投げ銭への自然な導線。

### 3-2. SS1 サブキャプションの差し替え

**旧（有料時代）:**
- JA: 買い切り。サブスクリプションなし。
- EN: One-time purchase. No subscription.

**新（無料時代）:**

| 案 | JA | EN | 意図 |
|---|---|---|---|
| **A（推奨）** | すべての機能を、無料で。広告もデータ収集もありません。 | Every feature, free. No ads, no tracking. | 無料アプリにありがちな「広告」「データ収集」への警戒を解除しつつ、肯定文で始めることで柔らかいトーンを保つ |
| B | 必要なもの、すべて。それ以外は、なにもない。 | Everything you need. Nothing you don't. | 機能の完全性を訴求。ただし無料であることが伝わらない |
| C | ずっと無料。ずっと、あなたのもの。 | Free forever. Yours to keep. | 将来の有料化予定と矛盾するため不採用 |

**案Aを推奨する理由:**

- 「すべての機能を、無料で」と肯定文で始めることで、ぶっきらぼうな印象を避けつつ、無料であることを冒頭で宣言する。
- 「広告もデータ収集もありません」は、無料アプリをダウンロードする際のユーザーの最大の懸念2つを先回りで解消。「ありません」という丁寧な否定で、ブランドの静謐なトーンを維持。
- 既存ブランドボイスの引き算の思想との一貫性を保ちつつ、短文の羅列（「X。Y。Z。」）ではなく文としてまとめることで柔らかさを加える。

### 3-3. その他のSSへの影響

| SS | 変更点 |
|---|---|
| SS2 | 変更なし。「集中中、すべてが消える」のメッセージは価格モデルに依存しない |
| SS3 | 変更なし。Auto-startの訴求は不変 |
| SS4 | 変更なし。Live Activityの訴求は不変 |
| SS5 | サブキャプションの「ユニバーサル購入」を再考。無料であればユニバーサル購入は自明なので訴求力が下がる。代替案: 「iPhone + Mac + Apple Watch。すべて同期。」/ "iPhone + Mac + Apple Watch. Always in sync." エコシステム統合の深さにフォーカスを移す |

### 3-4. 説明文冒頭3行の修正

**旧:** 集中は、静けさの中にある。 / 余計なものを一切持たない / 買い切り。サブスクリプションなし。

**新:** 集中は、静けさの中にある。 / 余計なものを一切持たない / 無料。広告なし。あなたのデータは、あなたのもの。

3行目を「価格の正当化」から「信頼の宣言」に転換する。

## 4. Patreon / 支援セクションのデザイン

### 4-1. デザイン原則

支援セクションの最大のリスクは「ブランドの品格を損なうこと」。Kokukokuの世界観の中に支援動線を溶け込ませるための5原則:

1. **頼まない。選択肢を置く。** 「支援してください」ではなく「支援という選択肢があります」。命令形・懇願形を一切使わない。
2. **理由を先に語る。** ボタンの前に「なぜこのアプリが無料なのか」「個人で作り続けるとはどういうことか」を1-2行で。支援は「共感の表明」であり「対価の支払い」ではない。
3. **面積を抑える。** 支援セクション全体の高さはビューポートの50%以下。スクロール全体の中で存在感を主張しない。
4. **有彩色の使用を最小限に。** Patreonのブランドカラー（コーラル）はアイコンにのみ使用。ボタン自体はブランドのCapsuleスタイルを維持し、tertiary fillで。
5. **1つのアクション。** 支援の選択肢は1つだけ。複数のTier、複数のプラットフォーム、複数の金額をLPに並べない。「Patreonで応援する」の1ボタン。詳細はPatreonページで。

### 4-3. コピーのバリエーション

| 言語 | コピー |
|---|---|
| JA | Kokukokuは、ひとりの開発者が時間をかけて作り続けているアプリです。もし気に入っていただけたなら、応援していただけるとうれしいです。 |
| EN | Kokukoku is made by a solo developer, one commit at a time. If it earns a place in your workflow, consider supporting its future. |

**トーンの設計意図:**

- 「ひとりの開発者」は事実の陳述であり、同情の喚起ではない。
- 「時間をかけて作り続けている」は現在進行形。「作った」（完了）ではなく「作り続けている」（継続）。支援は完成品への対価ではなく、継続への投資。
- 「応援していただけるとうれしいです」は条件付き（「もし気に入っていただけたなら」）であり、無条件の要請ではない。
- 英語版の "one commit at a time" は開発者ペルソナ（A）への直接的なシグナル。

### 4-4. App Store説明文への支援導線

App Store説明文内にPatreonリンクを直接埋め込むのは避ける（Appleのガイドラインへの抵触リスク + ブランドトーンの毀損）。代わりに:

- LP（Webサイト）のURLをApp Store「サポートURL」「マーケティングURL」に設定
- LP上で支援導線を完結させる
- アプリ内の設定画面最下部に「Webサイト」リンクを1つ。そこからLPの支援セクションへ

## 5. 制作者紹介セクションのデザイン

### 5-1. 設計思想

制作者紹介は「ポートフォリオ」ではなく「プロダクトの文脈」として機能させる。訪問者が知りたいのは「誰が作ったか」ではなく「どんな思想で作られたか」。顔写真や経歴ではなく、開発の哲学とプロセスを見せる。

**参照点:** Panic（Transmit, Nova）のAboutページ。制作者の人格は滲むが、あくまでプロダクトが主役。

### 5-2. ビジュアル構成

```
+----------------------------------------------------------+
|                                                          |
|  背景: #F2F0ED（S6支援セクションと地続き）                   |
|                                                          |
|     つくっているひと                                       |  ← H2: 32px, Light, #1A1A1A
|                                                          |
|     +-------+                                            |
|     | Avatar|  開発者名                                   |  ← アバター: 48px 円形
|     +-------+  @handle                                   |     グレースケール or イラスト
|                                                          |     写真ではなく抽象的な表現を推奨
|                                                          |
|     「時間を測るだけの道具に、                               |
|      なぜここまで手をかけるのか。                            |  ← 引用形式: 17px, italic相当
|      それは、毎日使うものだから。」                          |     和文はカギ括弧で引用を表現
|                                                          |
|     Kokukokuは、すべてのコードを                            |
|     ひとりで書いています。                                  |  ← 本文: 17px, #1A1A1A
|     外部ライブラリはゼロ。                                  |     2-3行の短い散文
|     あなたのデータを収集する仕組みも、                       |
|     ゼロ。                                                |
|                                                          |
|     [ GitHub ]  [ X (Twitter) ]                          |  ← テキストリンク: 14px, #888888
|                                                          |     アイコンなし。テキストのみ。控えめに
|                                                          |
+----------------------------------------------------------+
```

### 5-3. 設計判断

**顔写真を使わない理由:** Kokukokuのブランドは「プロダクト中心」。制作者の顔が前面に出ると、「個人のプロジェクト」というフレーミングが強くなり、「プロフェッショナルな道具」というポジショニングが弱まる。代わりにアバター（抽象的なイラスト or グレースケールのシルエット）を使用。

**経歴を書かない理由:** 「〇〇社で△年」「□□大学卒」のような経歴は権威の借用であり、Kokukokuのブランドボイス（「語りすぎない」）と矛盾する。プロダクトの品質そのものが唯一の資格。

**引用を使う理由:** 1行の引用（「なぜここまで手をかけるのか」）が制作者の人格を滲ませる最も効率的な手段。長文の自己紹介よりも余韻が残る。

**「外部ライブラリはゼロ」を明記する理由:** これは技術的事実であると同時に、ペルソナA（ナレッジワーカー / エンジニア）への直接的なシグナル。「Data Not Collected」と合わせて、「このアプリには不要なものが何も入っていない」ことの技術的な裏付け。

### 5-4. SNSリンクの扱い

- GitHub と X (Twitter) のリンクのみ。LinkedInやポートフォリオサイトは置かない。
- リンクはテキストのみ（`GitHub` `X`）。アイコンバッジは使わない。控えめであること。
- リンク色は `#888888`（セカンダリテキスト色）。ホバーで `#1A1A1A` に。
- リンクはセクション内の最下部、小さく。視線の終点に置く。

## 6. 全体のビジュアルコンシステンシー

### LP x アプリ x App Store の三者統一ルール

| 要素 | アプリ | LP | App Store SS |
|---|---|---|---|
| タイマー数字 | 100pt, thin, monospacedDigit | 96px, thin, tabular-nums | スクリーンショットに含まれる |
| ボタン | Capsule, tertiary fill | Capsule, tertiary fill | スクリーンショットに含まれる |
| サーフェス | .ultraThinMaterial + grain | backdrop-filter + grain PNG | スクリーンショットに含まれる |
| 色彩 | モノトーン + primary action のみ有彩色 | モノトーン + DL/支援ボタンのみ有彩色 | 白背景、アプリUI以外に有彩色なし |
| 書体 | SF Pro / SF Mono | Inter / ui-monospace (SF Mono fallback) | SF Pro (スクリーンショット内) / ヒラギノ (キャプション) |
| 有彩色 | system blue (primary action) | #007AFF (DLボタン) | アプリUI内のみ |
| ダークモード | 対応済み | 対応済み（`prefers-color-scheme: dark`） | SSはライトモードのみ |

### ダークモード対応

LPはローンチ時からダークモードに対応する。`prefers-color-scheme: dark` に応じてカラーパレットを切り替える。grain texture と glass surface はダークモードでも適切に調整し、暗背景上でのノイズ感とガラス表現の繊細さを維持する。
