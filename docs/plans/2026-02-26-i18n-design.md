# i18n (Japanese Localization) Design

**Goal:** Add Japanese localization to Kokukoku using Xcode String Catalogs so the app reads naturally for Japanese-speaking users while keeping English as the development language.

## Current State

- No localization infrastructure exists. All user-facing strings are hardcoded English.
- ~70 strings across 4 targets (App, Watch, Widget, LiveActivity) need localization.
- The app name "Kokukoku" is a Japanese word already — it should NOT be translated.

## Approach: Xcode String Catalogs (.xcstrings)

Use Xcode's modern String Catalog format rather than legacy `.strings` / `.stringsdict` files.

**Why:**
- Auto-extracts `Text("literal")` strings from SwiftUI views at build time
- Single JSON file per target — no per-language `.lproj` folders to manage
- Built-in pluralization support
- Xcode UI shows translation completeness at a glance

## Target Strategy

Each Xcode target gets its own String Catalog because String Catalogs are per-target in Xcode:

| Target | Catalog File | Membership |
|--------|-------------|------------|
| Kokukoku (iOS/macOS app) | `Kokukoku/Localizable.xcstrings` | Kokukoku target only |
| KokukokuWatch | `KokukokuWatchExtension/Localizable.xcstrings` | KokukokuWatch target only |
| KokukokuWidget | `KokukokuWidget/Localizable.xcstrings` | KokukokuWidget target only |

The pbxproj `knownRegions` must be updated to include `ja` (currently only `en` and `Base`).

Shared domain types (`SessionType.title`, `BoundaryStopPolicy.title`) live in the app target. The Watch target has its own duplicated title properties in `WatchSessionStore.swift` — these need parallel localization.

## Implementation Rules

### 1. SwiftUI `Text` Literals → Auto-extracted

SwiftUI `Text("literal string")` is auto-extracted by Xcode String Catalogs. No code change needed for these — just add translations in the catalog.

### 2. Computed String Properties → `String(localized:)`

Properties that return raw `String` (e.g. `SessionType.title`, `BoundaryStopPolicy.title`, `primaryActionTitle`) must be wrapped:

```swift
var title: String {
    switch self {
    case .focus:
        String(localized: "Focus")
    case .shortBreak:
        String(localized: "Short Break")
    case .longBreak:
        String(localized: "Long Break")
    }
}
```

### 3. Brand Names → `Text(verbatim:)`

"Kokukoku" must NOT be extracted for localization:

```swift
Text(verbatim: "Kokukoku")
```

For non-SwiftUI contexts (e.g. `LiveActivityService`), the string `"Kokukoku"` is already a raw `String` literal passed to `activityTitle` — no localization needed.

### 4. HistoryFilter rawValue Separation

`HistoryFilter` currently uses English `rawValue` for both identity and display. Separate these:

```swift
private enum HistoryFilter: String, CaseIterable, Identifiable {
    case all, focus, breaks

    var id: String { self.rawValue }

    var title: String {
        switch self {
        case .all: String(localized: "All")
        case .focus: String(localized: "Focus")
        case .breaks: String(localized: "Breaks")
        }
    }
}
```

### 5. String Interpolation with Localized Strings

For strings like `"Focus: \(minutes) min"`, use SwiftUI's automatic LocalizedStringKey interpolation:

```swift
Text("Focus: \(store.config.focusDurationSec / 60) min")
```

This is already auto-extracted by String Catalogs with a placeholder. The Japanese translation uses the same placeholder: `"集中: \(minutes)分"`.

### 6. Notification Strings — Per-Type Complete Sentences

Avoid string interpolation for notification titles. Use complete per-type sentences for natural translation:

```swift
func notificationTitle(for sessionType: SessionType) -> String {
    switch sessionType {
    case .focus:
        String(localized: "Focus completed")
    case .shortBreak:
        String(localized: "Short Break completed")
    case .longBreak:
        String(localized: "Long Break completed")
    }
}
```

This avoids word-order issues where `"\(type) completed"` would produce unnatural Japanese.

### 7. Diagnostics Error Messages

Wrap user-visible error messages in `String(localized:)`:

```swift
self.lastErrorMessage = String(localized: "Failed to load preferences: \(error.localizedDescription)")
```

- Only English (base) and Japanese in this pass
- No RTL considerations (Japanese is LTR)
- No plural rules needed (Japanese has no plural forms)
- InfoPlist.xcstrings for App Store display name is out of scope (the app name "Kokukoku" is language-neutral)
